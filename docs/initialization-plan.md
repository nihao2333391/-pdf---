## 1. 初始化的交付目标

建立一个能够被微信开发者工具导入和编译的小程序工程，具备基础首页、明确的启动方法和类型检查入口。在具备账号与设备条件后，使用 Android 微信打开基础首页。

文件处理库现已接入：pdf-lib、Docxtemplater 与 PizZip 由 esbuild 预先打包为本地 CommonJS。`npm.cmd run build` 可复现构建，`npm.cmd test` 运行真实文件流程测试。原“优先专项验证”的设计已得到电脑验证证据，Android 证据待补充。

## 3. 规划的目录与职责

以下是计划结构。启动入口、基础首页、配置与说明文件已建立，其他业务模块随开发创建。当前实际落盘内容以项目文件为准。

```text
项目目录/
├── README.md                    # 启动方法、检查命令、当前完成程度
├── AGENTS.md                    # 本项目协作规则与新对话读取顺序
├── package.json                 # 依赖清单、类型检查等命令
├── package-lock.json            # 安装时生成，固定实际依赖版本
├── project.config.json          # 微信开发者工具的工程配置
├── tsconfig.json                # TypeScript 类型检查范围与规则
├── .gitignore                   # 本地配置、依赖、构建产物等排除规则
├── .npmrc                       # 官方包源、项目内缓存和精确版本设置
├── docs/
│   ├── requirements.md          # 已确认需求与验收案例
│   ├── technical-design.md      # 数据约定、模块职责、方案比较
│   ├── initialization-plan.md   # 本方案
│   └── progress.md              # 初始化后记录任务、证据和下一步
└── miniprogram/
    ├── app.ts                   # 小程序启动入口
    ├── app.json                 # 页面注册与窗口配置
    ├── app.wxss                 # 公共样式
    ├── pages/home/              # 初始首页，含 ts/json/wxml/wxss
    ├── models/                  # 后续集中定义记录、费用组和材料类型
    ├── services/                # 后续加入草稿仓库和生成协调器
    ├── adapters/                # 后续加入微信文件、PDF、Word 适配器
    └── assets/                  # 后续加入本地 Word 模板等程序资源
```

初始化先建立实际使用的入口与配置。其他模块目录在对应代码加入时创建。历史页、报销编辑页、费用组编辑页和结果页随各段完整流程逐步接入。

材料位于手机的小程序文件空间；程序资源位于代码目录。验证材料优先使用自行构造或脱敏样例，避免把真实报销材料混入发布代码包。

## 4. 具体配置方式

| 配置 | 初版安排 | 原因与依据 |
|---|---|---|
| 工程类型 | 微信原生小程序 | 技术设计已比较原生、Taro 和 uni-app；首版面向微信文件能力 |
| 语言与页面 | TypeScript、WXML、WXSS | 页面结构和逻辑直接对应微信能力；类型检查用于保持模块数据一致 |
| 微信工程配置 | `compileType` 为 `miniprogram`，`miniprogramRoot` 为 `miniprogram/`，启用 TypeScript 编译支持 | [微信官方示例配置](https://github.com/wechat-miniprogram/miniprogram-demo/blob/master/project.config.json)提供参考；本项目只保留所需字段 |
| 类型定义 | 使用 `miniprogram-api-typings`，在 TypeScript 配置中引用 | [微信官方类型定义说明](https://github.com/wechat-miniprogram/api-typings)给出安装和引用方式 |
| 类型检查 | 提供 `npm.cmd run typecheck`，以 `tsc --noEmit` 检查项目源码 | 在微信编译之前发现字段或函数调用不一致的问题 |
| 依赖管理 | 使用项目根目录的 npm 清单和锁文件；安装时记录准确版本 | 后续对话和重新安装使用同一依赖依据 |
| 生产依赖打包 | 接入处理库时，明确配置根目录 npm 清单与小程序输出目录的关系，并验证微信“构建 npm”产物 | [官方示例使用说明](https://github.com/wechat-miniprogram/miniprogram-demo#使用)包含构建 npm 步骤；具体配置在所用工具版本中确认 |
| AppID 与本地设置 | 使用本项目真实 AppID；个人开发者工具设置单独保存；AppSecret 等凭证保持在受保护的账号管理范围 | 本机文档处理采用客户端文件能力，工程配置按实际需要填写 |
| 运行版本 | 初始化时记录开发者工具与基础库版本，按候选依赖和真机情况确定兼容范围 | 所用基础库须覆盖实际接口，模拟器和手机分别验证 |

安装依赖前再次核实官方发布包与许可。初始工程只加入开发必需依赖，PDF 与 Word 依赖分别在专项验证阶段加入。

| I-02 最小工程 | 创建启动入口、基础首页、配置、运行说明及协作规则；安装基础开发依赖 | 类型检查通过；微信开发者工具编译并显示基础首页 | 电脑检查已通过，模拟器已显示首页；完整布局及控制台提示继续核对 |
| I-03 Android 预览 | 使用微信在 Android 打开该工程 | 手机实际打开基础首页，记录设备和运行版本 | 待验证 |
| V-01 导入与保存 | 搜索筛选相关实现后，接入材料选择、复制、记录保存与重开 | 验证需求 AC-01、AC-06 的基础保存路径 | 待开发、待验证 |

| V-03 方案回写 | 记录实际采用版本、失败样例、资源限制及替代方案结果 | 技术设计与依赖记录和实际代码一致 | 待执行 |

I-02 成功说明开发环境和基础工程可用。I-03 成功说明所测手机能够运行基础工程。材料合成是否可用，由 V-01、V-02 的独立证据确认。

后续完整功能按“新建并保存一组 → 多组编辑和拖拽 → 生成与导出 → 历史重新编辑”的操作链逐段整合。每一段同时检查新行为与已经完成的相关行为。

## 6. AI 协作与新对话接手约定

初始化时将以下约定写入项目协作说明，并持续维护进度记录：

1. 接手时先阅读项目协作说明、需求、技术设计和当前进度，再核对相关代码及已有检查结果。
2. 每个任务写明目标、输入输出、涉及模块、依赖任务、验收方式和当前状态。
3. 每个技术环节开始编码前，上网搜索并比较已有代码；记录采用或排除理由。由开发助手完成技术筛选。
4. 统一使用集中定义的数据类型和仓库入口。发现数据约定需要调整时，同步检查所有使用位置并更新技术设计。
5. 完成任务时记录修改内容、检查命令、结果、真实设备验证状态和下一步。将“资料判断”“电脑检查通过”“Android 实测通过”分开标记。
6. 用户需求变化时更新需求依据，并检查受影响的技术设计、代码和验收案例。保留与恢复能力相关的旧版本信息。
